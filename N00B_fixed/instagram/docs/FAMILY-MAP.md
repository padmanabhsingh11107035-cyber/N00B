# NOOB Family Map

A room for a family (or friends) where everybody sees everybody's live place on a detailed world map. Free, optional, shown only to the people in the room, and **end-to-end encrypted**.

**Where to open it:** a round map-pin button on the Messages page (next to search and find-a-person), the Home menu entry, or the address below.

**Address:** `https://noobsocials.com/family` (a page of its own, `family.html`) and the same screens inside the app (Home menu > Family Map). Open `https://noobsocials.com/family?demo=1` for a made-up demo that needs no account and no database. An invitation link looks like `https://noobsocials.com/family#join=K7QM2XPD` (the code sits after the `#`, so no server ever sees it).

## What a person sees
1. **First page**: the turning earth on top (35% of the screen), the two buttons **Create room** and **Join room**, "Your rooms" (tap a room: no code to type again) and the switch **Share my location**.
2. **Allow location** (only the very first time): why it is needed, then the browser's own question. After that nothing is asked again: the permission is remembered by the browser, and NOOB remembers that the person allowed it (`src/family/consent.ts`). The person turns sharing off with the one switch (or takes the permission away in the phone's settings); a person who switched sharing off is never asked at all, and rooms they make or join start paused.
3. **Create room**: a name and a picture; then the room's **code** (8 letters and digits, shown as `K7QM-2XPD`) with Share invite / Copy code. **Join room**: type the code once.
4. **A room**: the detailed map full-screen, every person's profile picture on their exact place with their first name, a dot on the spot, a green ring when they are live. A sheet lists the people (live / "Last seen 5 min ago" / "Paused sharing", distance from you, "Moving 24 km/h"). Buttons: show everyone, show me, night / streets, 3D. Menu: code, share my location, keep screen on, **lock the room** and new code (owner), delete room (owner), leave room. A toast says when somebody new joined.

## Sharing when the app is closed
- **Browser / iPhone / installed web app**: a web page can only learn the phone's place while the page is open (iPhone and Android stop it when the screen locks). While NOOB is open on any screen, sharing goes on by itself for a person who turned it on (`FamilyTracker`, mounted in `App.tsx`; it loads nothing for people who never used Family Map and never asks for a permission on its own). On iPhone the website cannot do more: there is no iPhone app.
- **NOOB Android app**: sharing goes on while the app is closed, through a foreground service (the plugin `@capacitor-community/background-geolocation`, MIT, only its native Android part, called by name in `src/family/background.ts`). Android shows a notification the whole time. The person can switch this off on the first page ("Keep sharing when NOOB is closed"). The CI build checks that the plugin is linked (`android-build.yml`). Needs a new APK (the in-app "Update NOOB" button) and the phone's location permission; when the person publishes on Google Play, "background location" must be declared in the Play Console.

## How it works
- **Map**: MapLibre GL 6 (WebGL; 6.5 or newer, because every older version has a known script-injection flaw in its popup cleaner, which `npm audit` in the CI reports), loaded only when a map is shown (its own chunk, about 1 MB, plus the worker file `maplibre-gl-worker-*.mjs`: the library looks for its worker next to its own file, which a build renames, so `MapCanvas.tsx` tells it where the file is with `setWorkerUrl`). The pictures come from OpenFreeMap (free, no key, OpenStreetMap data); its "liberty" style is recoloured into the night look in `src/family/mapStyle.ts`. If OpenFreeMap cannot be reached a plain OpenStreetMap picture is used. The first page uses the globe projection with an atmosphere.
- **Database** (migrations `20261031000001_family_map.sql` and `20261031000002_family_sealed.sql`): tables nobody can read or write directly (row-level security, no policy, nothing granted) and `family_*` functions that check who is asking: `family_create_room`, `family_join_room`, `family_my_rooms`, `family_room_state`, `family_room_keys`, `family_push_sealed`, `family_set_sharing`, `family_set_sharing_all`, `family_my_prefs`, `family_set_locked`, `family_leave_room`, `family_remove_member`, `family_rotate_code`, `family_delete_room`.
- **Live places**: the phone follows its own place and sends it when it moved 8 m (at most every 4 s), or every 20 s as a heartbeat; the room is read every 5 s while the page is on the screen. Pins glide between readings.
- **Encryption (end to end)**: a place is locked on the phone before it leaves it, with the same locking as NOOB chats (`src/e2ee/crypto.ts`, WebCrypto: a device key pair per phone, the place locked with a fresh AES-GCM key, that key locked for every device of every person in the room). `src/family/sealed.ts` does it; `liveApi.ts` sends the envelope with `family_push_sealed` and opens the others' envelopes after `family_room_state`. The database keeps only the locked envelope (it contains no coordinate) and hands each person the envelope reduced to the locks of their own devices. The lock names who made it (nobody can put a place in somebody's name, not even the server) and the room it belongs to (a copy in another room does not open). A place that says it is much older than the server's clock is shown as older. Nothing readable is kept: the old plain table `family_locations` and its function were removed. What it does not give: the server hands out the public keys (so a server that is itself the attacker could add itself; people can compare security codes in a chat), and there is no ratchet (an unlocked, stolen phone can read what is on it). NOOB can still see the room's name, who is in it, whether they share and when a place was last sent, not where it was.
- **Privacy**: only the last (locked) place of a person in a room is stored (one row, replaced each time; no history, no trail). It is shown only to people in that room while that person shares with it, hidden after 24 hours without news, removed when sharing is paused, when the person leaves, and when the account is deleted. Administrators cannot read places (nobody can). The phone saves only the last room, the map style and yes/no switches, never a place.
- **Codes and rooms**: 8 symbols from a 32-symbol alphabet without look-alikes (I, O, 0, 1), from the database's secure random numbers. 8 wrong codes in 10 minutes pause a person for 10 minutes. The owner can make a new code (the old one stops at once), remove a person, **lock the room** (nobody new can join, even with the code) or delete it. Limits: 20 people per room, 10 rooms per person. If the person who made a room deletes their account, the room goes with it.
- **Admin switch**: Admin > Pages > Family Map hides the menu entry and the database refuses new rooms, members and places (nothing is deleted).
- **Security headers**: `/family` has its own policy in `public/_headers` (the two map servers and the database only; the whole site's policy names the two map servers too, because the app shows the same map inside itself).
- **Legal pages** that say all of this: Privacy Policy (`PrivacyPolicy.tsx`, `public/privacy.html`), Terms (`TermsAndConditions.tsx`, `public/terms.html`: consent of everybody, no following of a person who has not agreed, a guardian is responsible for a child, not an emergency service), the encryption page (`EndToEndEncryption.tsx`) and `public/data-deletion.html`.

## Run / test
`npm run dev:web` then `/family?demo=1`. Tests: `node --liftoff-only scripts/supabase/test-family.mjs` (logic, the tracker, the locking with the real code against the real database rules on a real Postgres, wiring, the legal pages). Look: classes all start with `fm-` (`src/components/Family/family.css`).
