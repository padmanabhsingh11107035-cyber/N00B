# Games on their own address (finding M2)

Problem: the games are folders of files on the app's own address (`/games/<name>/`), shown in a frame with `allow-scripts allow-same-origin`. Any script in a game (many are ported or compiled third-party code) can therefore read the app's Supabase sign-in from `localStorage` and act as the signed-in player.

## What is in the code today (nothing changes until you do the steps below)

1. **No honest way to hide the session on the same address.** The session lives in the page's `localStorage`. Any script on the same origin can read it, whatever supabase-js does in the parent (memory, IndexedDB, a custom storage object: all are reachable from the same origin, and a game can also reach `window.parent` and the parent's JavaScript objects). This is not fixable on one origin, so nothing was faked. The only real fix is a different origin.
2. **Separate games address, off by default.** `VITE_GAMES_ORIGIN` (build-time, see `.env.example`). Empty = identical behaviour to before. When set (for example `https://games.noobsocials.com`):
   - `HostedGameFrame` loads `GAMES_ORIGIN + /games/<name>/#noob-parent=<app origin>` and keeps `allow-same-origin` (harmless there: that origin holds no sign-in), so every game keeps its own saves.
   - the postMessage bridge (ranking, score, online race) accepts a message only if `e.source` is that frame **and** `e.origin` equals the games origin exactly, and every reply is addressed to that exact origin (never `*`).
   - on the game side, `_shared/noob-score.js`, `brick-escape/game.js` and `color-sort/game.js` read the app's origin from the `#noob-parent=` fragment (only when it differs from their own origin) and use it as target and as the accepted origin. Without the fragment they behave as before.
   - code: `src/utils/gamesOrigin.ts` (`planGameFrame`), `HostedGameFrame.tsx`, flags in `src/components/Games/types.ts`.
3. **noob_run_3d, critter_kart and Helix Fall now move too.** Their built bundles had `window.location.origin` compiled in as the message target and the accepted origin. Those places (2 in each of noob-run-3d and critterkart, 6 in helix-fall, plus the helix `embed-probe.js`) were replaced, byte for byte otherwise, by an expression that reads the `#noob-parent=` fragment (only when it differs from the game's own origin) and falls back to the own origin. Because bundles are cached for a year they were renamed: `index-RczImZTD-n1.js` (noob-run-3d), `index-CHyWxhOt-n1.js` and `game-vtuqf7t6-n1.js` (critterkart), `index-b2ec185e-n1.js` (helix-fall); index.html and warm.json name the new files, `embed-probe.js` is loaded as `?v=2`. `HelixFallGame.tsx` now uses `planGameFrame` and the same sandbox as the other games. Rollback: restore the old files (git history) and set `sameOriginOnly: true` again (the option still exists in `planGameFrame`). Helix's share link (`?c=`) is built from the page's own origin, so with the games address it points at `games.noobsocials.com/games/helix-fall/`, which serves the game standalone.
4. **`isolated: true`** (works today, on the app's address): the frame gets no `allow-same-origin`, so the game runs in an opaque origin and cannot read anything of the app. Only for games that tolerate refused storage and have no bridge. Currently `royal_ludo` and `nocta_uno` (both verified: every storage access is inside try/catch). Their saves (Ludo stats, an unfinished UNO game) are then not kept between visits; Ludo shows its own "Browser storage unavailable" note. Existing saves in the browser are not deleted. The flag is ignored for any game with a ranking, score or race (an opaque frame cannot be addressed safely).
5. **Worker:** `worker/index.js` answers 404 for everything except `/games/*` on the host(s) listed in `GAMES_HOSTS` (`games.noobsocials.com`), so the app itself is never served from the games address. Folders excluded from the worker in `wrangler.jsonc` (`/assets/*`, `/brand/*` ...) are still plain static files there; harmless, they hold no secrets.
6. **`public/_headers`:** the games' CSP now says `frame-ancestors 'self' https://noobsocials.com https://www.noobsocials.com` (was `'self'`), and the games' `X-Frame-Options: SAMEORIGIN` lines were removed (that header cannot name another site and would block the app from framing the games address; `frame-ancestors` is the control and is supported by every current browser). Games can therefore be framed only by the app (and by themselves). The rule count stays below 100.

## Games that need saved data, and why they are not isolated

Almost every engine game (apexdrift, ashenfang, breachpt, coil-rush, critterkart, farbound, frostzero, helix-fall, lane-runner, noob-run-3d, pulsegrid, siegecraft, strikebowl, terrafoundry, the-rogue, underhall, canyon-rush) builds a save object with `constructor(storage = globalThis.localStorage)` or reads `localStorage.getItem` without a guard: in an opaque origin that throws `SecurityError` at start-up and the game would not open. noobgames-hub (`getWins`) and metro-rush read it unguarded too. neon-alley and vertical-platformer use IndexedDB (Godot/emscripten file system). Bridge games (flappy20, noob-run-3d, color-sort, brick-escape, critter-kart) need a usable origin for their messages. Those games only become safe through the separate address.

## Owner steps for the separate address

1. **Cloudflare, Workers & Pages, worker `n00b`, Settings, Domains & Routes, Add, Custom domain:** `games.noobsocials.com`. (The DNS record is created by Cloudflare itself since the zone `noobsocials.com` is there. Same Worker, same assets. Wait until the certificate shows Active.)
2. Check (a browser or `curl -I`): `https://games.noobsocials.com/games/royal-ludo/` loads (200) and shows `content-security-policy: ... frame-ancestors 'self' https://noobsocials.com https://www.noobsocials.com`; `https://games.noobsocials.com/` answers **404** (the app is not served there).
3. **Supabase:** nothing to add. The games never talk to Supabase themselves (their CSP is `connect-src 'self'`); the score/ranking calls are made by the app.
4. **Build setting:** add the variable `VITE_GAMES_ORIGIN` = `https://games.noobsocials.com` in Cloudflare (Workers Builds, Settings, Variables and secrets, **build** variable) and redeploy. To roll back, delete the variable and redeploy; behaviour returns to the current one.
5. Do **not** put the app's own CSP `frame-src` in the way: the app's CSP has `frame-src https:` (public/_headers, rule `/*`), so framing `https://games.noobsocials.com` is already allowed. If `frame-src` is ever narrowed, add the games address.
6. After the switch, test on a phone: open one game from each family (a score game such as Flappy, Color Sort, an engine game such as Siegecraft, Royal Ludo) and check that the trophy/ranking button works.

## What the owner should know before switching

- **Saves start empty.** Each game's saved data (bests, unlocked skins, settings, unfinished runs) lives in the browser storage of the address it ran on. On the games address that storage is new and empty. Nothing is deleted (the old saves stay on the app's address, unreadable by the games) but players will see their local game progress reset. Rankings and NOOB payouts are in the database and are not affected. If that is not acceptable, a one-time copy needs a small bridge page on the app's address that posts each game's keys to the games address; ask for it before switching.
- The warm-up code (`utils/*Warmup.ts`) still pre-fetches the big games' files from the app's address; after the switch that pre-fetch no longer helps (it warms the wrong address) and costs bandwidth. It can be pointed at `GAMES_ORIGIN` in a later change (those files would then need CORS headers or `no-cors` fetches).
- Games on the games address share one origin among themselves: one game's script could read another game's saves there (never the app's sign-in). That is the same as today.
