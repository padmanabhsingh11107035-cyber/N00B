# Design brief for the NOOB page redesigns (read fully before touching anything)

The owner looked at the first redesign (purple/pink/violet gradients, glass cards, glowing blobs, floating orbs, gradient headline text, emoji decoration) and said: **"looks vibe-coded, very bad UI/UX, unorganised design, use other colours, component placing is not accurate."** This round must feel like a real product designed by a person: Linear, Revolut, Spotify, Things, Arc. Not an AI landing page.

## What "not vibe-coded" means here
- **No**: backdrop blur / glassmorphism cards, glowing blobs, drifting orbs, gradient text, rainbow or multi-stop gradients as decoration, neon box-shadow glows, emoji used as decoration, centred-everything layouts, five different radii, tiny low-contrast grey text, every card the same size with the same icon.
- **Yes**: ONE accent colour per page on a neutral base (a second colour only where it carries meaning, e.g. rarity, vote side), solid fills, 1px hairline borders, one radius scale (8 / 12 / 16 / 24), a strict 4/8 px spacing grid, one consistent horizontal page margin (16 px), left-aligned text, a clear type scale (at most 3-4 sizes per screen, real weight contrast), numbers set large and tidy, aligned baselines, 44 px minimum touch targets, one primary action per screen, obvious grouping (section titles, dividers, whitespace), tidy empty/loading/error states, motion that is quick (120-220 ms) and purposeful (press feedback, bar growth, sheet slide), `prefers-reduced-motion` respected.
- Component placing must be exact: things that belong together are visibly together and aligned to the same edges; headers have the back button at the same place on every page; primary action reachable by thumb (bottom area on phones); nothing cut off at 360 px width; long text truncates or wraps intentionally.

## Full screen, from above the notch to the bottom
On phones the app adds `phone-edge` to `<html>` and the CSS variable `--sat` (top safe-area height). `index.css` pushes every `.fixed.inset-0` layer down to `top: var(--sat)` UNLESS it has class `edge-own`. So the page root must be `fixed inset-0 edge-own` (keep the existing z-index), paint its own background all the way to the very top, and pad its header with `padding-top: calc(var(--sat, 0px) + 12px)`. Pad the bottom with `env(safe-area-inset-bottom)`. Content scrolls inside the page; the header can be sticky.

## Both themes
Dark is the default; light is `:root[data-theme="light"]`. Define colours as CSS variables on your page root class and override for light. Light mode must look as intentional as dark (not an inverted afterthought). `index.css` has many `!important` mono-theme overrides that flatten rounded cards and strip backgrounds (class `no-doodle` strips `background-image !important`): use your own prefixed classes and plain CSS with enough specificity; verify in the browser, do not assume.

## Palettes (one accent per page; the exact hex values are yours to tune by eye)
- NOOB Studio: graphite neutrals (#0E0F11 / #16181B / #1F2226), accent warm orange (#FF7A1A) for the active tool, playhead and Export; text near-white; light theme: warm greys.
- NOOB Draw: near-black with gold (#F2B63B) as the only accent; rarity colours (common grey, rare blue, epic purple, legendary gold) appear only on prizes.
- This or That: two solid, strongly contrasting side colours (cobalt #2F5BFF vs tangerine #FF7A2F) on an ink / cream base.
- Ask Me Anything: warm paper (cream #FBF4E8) with terracotta (#D9482B) accent; dark theme warm charcoal (#1B1715) with the same accent.
- Public Polls: deep ink navy (#0A1724) with teal-mint (#19C3A6) accent, solid bars; light theme cool white with the same teal.
- Anonymous Messages: charcoal (#121212) with acid lime (#C8F031) accent, message bubbles solid in a few muted tones; light theme off-white with a darker lime/olive accent.

## How to work (mandatory)
1. A dev server for the visual harness is already running at `http://127.0.0.1:5190` (if it is down: `npm run harness` in the background; never kill processes you did not start). Read `harness/README.md`. Always screenshot with `frame.html` (390x844 phone frame): `http://127.0.0.1:5190/harness/frame.html?page=<page>&theme=dark|light&phone=1` (`state=empty|loading|error`, `admin=1`, `doodle=0` etc. are listed in the README). You are the only agent using the Browser pane right now (tools `mcp__Claude_Browser__*`; use the one existing tab, navigate it; screenshot with `computer {action: screenshot}`; scroll with the `scroll` action to see the whole page). Use the pane's own scrolling and zoom; do not resize the pane to a phone preset (the frame does it).
2. Process: (a) screenshot the current state of every screen of the page in dark and light and write down in plain words what is wrong with layout, hierarchy, alignment and colour; (b) sketch the new layout in words (regions, order, sizes); (c) implement; (d) screenshot again in dark AND light, scroll through the whole page, check the empty/loading/error states; (e) criticise your own result like a harsh art director (alignment, spacing consistency, contrast, anything that still looks generated) and iterate at least three rounds before you finish.
3. DATA SAFETY (top priority): change markup and styles only. Never change API calls, RPC names, payloads, state/handler logic, data shapes, props contracts, routing, points/odds/votes/storage logic. You MAY reorder, regroup and restructure the JSX that is returned, add purely presentational elements, and change visible labels only when the old label was misleading (keep the meaning). Keep every `data-testid`, `aria-label`, role and the text that tests look for: `grep -rl "<ComponentName>" scripts/` and read those tests first; if an old assertion checks a class string you replaced, update it minimally and say so.
4. Replace the previous redesign's stylesheet for your page completely (rewrite it from scratch in the new direction); remove its now-unused classes.
5. Finish with: `npx tsc --noEmit -p .` clean, the related `node scripts/...test-*.mjs` passing (never the full suite; it takes 25+ minutes), and `node scripts/lint-text-fit.mjs` clean for your files. Do NOT run git commands. Do not touch `src/index.css`, `src/polish.css`, other pages' folders, `harness/` code (except you may add mock data to `harness/mocks.ts` if a state cannot be shown, say so).
6. Final reply: what the page looked like before and after (honest, in plain words), the self-critique points you fixed, anything still weak, test results.
